# USB実機比較：2026年11月4日

## 条件と方法

- MacBookAir9,1、Intel x86_64、8 GB、8論理CPU、macOS 15.8.1。
- A＝公式OpenDisplay 1.30.1、B＝カーソル変換を修正したローカル開発版。同じiPad、USB、H.264、1640×2360、拡張画面、localCursor=true、既定のBest画質。
- 同じ仮想画面上でCore Animationのバーを往復させ、ポインターは静止。軽量版→通常版→通常版→軽量版（BAAB）。各20秒の準備後、約60秒計測。
- アプリCPUは`proc_pid_rusage`のuser/system累積ナノ秒の差分÷実時間。100%＝1論理CPU。
- メモリは2秒ごとの`ri_phys_footprint`と`ri_resident_size`、計31点の単純平均。footprintを主指標とする。
- Mac全体CPUは`host_statistics`のuser/system/nice ticks÷全ticksの差分。100%＝全CPU。
- fpsなどは計測区間の受信側`PHONE-STATS`の試行内単純平均。各版の集計は各試行平均を測定時間で重み付けする。受信統計のサンプル数による重み付けではない。
- スワップはシステム全体の`vm_stat`ページ数の区間差分。アプリ単体のスワップ量ではない。

## 制約

各版2回の短時間比較で、統計的有意差を検証していない。他のアプリを閉じておらず、システムの負荷・スワップは変動している。公式配布バイナリとローカル開発バイナリではコンパイラ・ビルド条件が異なるため、パッチだけの効果を分離できない。

長時間の安定性、電力消費、カーソルを動かす操作、タッチ操作、他のハードウェア、全面的な画質比較はこの実験の検証対象外。ソース上では解像度、コーデック、フレームレート設定、カーソル位置の120 Hzサンプリングとタッチ経路を変更していない。

静止画で実施した先行試行は、フレーム受信がないと受信統計が出ず接続判定を満たさなかったため、全て除外した。ここに掲載するデータは動く画面で完了した4試行のみ。測定の終了後は軽量版を再起動し、実験専用バー表示を終了した。

## ファイルと再集計

- `protocol.json`：環境、順序、条件、公開用加工の説明。
- `trial-*.json`：各試行の数値時系列、受信統計、試行集計、スワップページ差分。
- `results.json`：4試行の集計。
- `summary.json`：各版の集計と差。
- `build-info.json`：配布アプリのバージョン、対象CPU、ソース識別子、SHA-256。

個人のファイル・画面内容・デバイス識別子は含めない。プロセスID、稼働時間、プロセス開始・終了tick、未使用のカウンターは除き、CPUナノ秒とシステムCPU tickを各試行の初期値からの差分にした。経過時間、メモリ値、性能統計、区間スワップ量は保持している。元のローカルデータは変更していない。

リポジトリ直下で次を実行すると、公開時系列から指標を再計算して、保存済みの全試行・版別集計と一致することを検証する。アプリの起動・終了は行わない。

```sh
python3 local-tools/analyze-published-results.py
```

## 再測定

`local-tools/ComparisonScene.swift`がアニメーション、`local-tools/compare-apps.py`がBAAB計測を実行する。既存スクリプトのディスプレイIDは元の試験環境用なので、接続先を確認してから変更する。Command Line Toolsでシーンをビルドする例：

```sh
mkdir -p build/comparison
xcrun swiftc -O local-tools/ComparisonScene.swift -o build/comparison/comparison-scene
```

通常版と開発版の画面収録を許可し、同じ受信側へ接続できることを確認する。計測スクリプトは両OpenDisplayを必要に応じて終了・起動するため、接続を中断できる時にだけ実行する。他のアプリは終了しない。出力先は実行ユーザーの`Documents/Mac診断/`。再計測の結果と今回の結果は別に扱う。
